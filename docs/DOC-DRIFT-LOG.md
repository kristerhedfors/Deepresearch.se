# Documentation drift log

Append-only ledger of **Class C** documentation drift — cases where the
code and a capability/architecture/privacy-posture claim in the canonical
docs disagreed, and the owner ruled which side was wrong. Maintained by the
**docs-drift-validation** skill; see it for the full workflow. Class M
(mechanical) drift is not logged here — it lands via **update-docs**.

Each entry records the finding, the owner's verdict, and how the checkmark
was given, so future validation runs can tell an owner-validated posture
change from an unexamined one. Only append, and only after the checkmark.

Entry format:

```
## YYYY-MM-DD — <one-line finding>
- **Doc claim:** <doc file> — "<quoted claim>"
- **Code:** <file:line summary> (introduced by <commit(s)>)
- **Verdict:** intended | regression — by owner via <PR #n merge / approving comment / AskUserQuestion>
- **Action:** <doc rewrite landed in …> | <code fix routed via …, doc unchanged>
```

## 2026-07-30 — invariant 6 broken silently by JavaScript's ASCII `\b` in nine bilingual gates
- **Doc claim:** `CLAUDE.md` invariant 6 — "Every regex gate / phrase set that routes behavior … must take Swedish forms with the same breadth as English." `docs/MERGED-BRANCHES.md`:111 already flagged the mechanism and that the audit was owed: "**Other bilingual gates in this repo are NOT audited for it**; the skill carries the grep."
- **Code:** the audit was run. JavaScript defines `\b` over `[A-Za-z0-9_]`, so an alternative starting or ending in `å`/`ä`/`ö` can never match against a `\b`. Ten dead alternatives across five modules, each confirmed empirically: `src/googlemaps-text.js:111` (`allé`) and `:152` (`på`), `src/model-checks.js:192` (`är`), `public/js/aadr-core.js:242` (`äldre än`), `public/js/bash-core.js:204` (`åt mig`), `public/js/canned-faq.js:34` (`är`, `åtkomst`, and the `hallå` branch of `hall[åa]`), `:204` (`åtkomst`), `:241` (`nivå`). Two were user-visible: `extractPlace("Vad finns på Storallé?")` returned `""` (no lookup at all) and `extractPlace("street view Storgatan på Gotland")` returned `"Storgatan"`, dropping the city — the wrong-city class that file's own comments warn about. The other sites were masked by an ASCII-tailed sibling or an `[åäö]` pre-test, which is exactly why an English-passing suite never caught any of it.
- **Verdict:** regression — the docs are the spec and the code was wrong. Owner via `AskUserQuestion` chose "Fix them in this pass".
- **Action:** code fixed, docs unchanged on the invariant itself. All ten alternatives now use the repo's existing lookaround idiom with the `u` flag — `(?<![\p{L}\p{N}_])…(?![\p{L}\p{N}_])`, the form `src/europepmc.js:112` names `B`. Parity cases added to each module's own suite (`src/googlemaps.test.js`'s "Swedish language parity" block, `src/model-checks.test.js`, `public/js/aadr-core.test.js`, `bash-core.test.js`, `canned-faq.test.js`'s `PROBES` table), and `src/model-checks.js` gained a `looksSwedish` export so the one check encoding invariant 6 has a testable verdict without a live provider. The whole CLASS is now guarded repo-wide by **`src/swedish-boundary.test.js`**, which scans every non-test module under `src/`, `public/js/`, `public/cure/` and `public/games/`, fails naming each unmatchable alternative and the fix, and carries a second test that guards the scanner itself. Documented in `docs/TESTING.md` (repo-wide guards) and routed for future regressions via a new `docs/MAINTENANCE-OWNERS.md` row (PR #332, the palaeogenomics agent, which found the mechanism).
